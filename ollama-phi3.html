What is Artificial Intelligence?

The Actual Definition

Artificial Intelligence is the field of building systems that perform tasks normally requiring human intelligence — understanding language, recognising patterns, making decisions, and solving problems by learning from data rather than following hardcoded rules.

Here's the honest version: for decades, AI was just very fancy if-else statements. You wrote every rule by hand. "If the email contains the word 'prince' and 'inheritance', mark as spam." Brittle. Exhausting. Didn't scale.

Modern AI flipped this. Instead of writing rules, you show it millions of examples and let it figure out the rules itself. That shift — from rule-based to learning-based — is what made the last decade happen.

🎯 The one-line distinction

Traditional software: you define the rules.  AI: you show it examples, it infers the rules. Everything else is implementation detail.

What is a Language Model?

Definition

A Language Model is an AI system trained to predict the next word (token) in a sequence — repeatedly, at scale, on trillions of words. The uncomfortable truth is that this embarrassingly simple objective, done at sufficient scale, produces a system that appears to reason, write, and understand.

The core architecture is the Transformer, introduced by Google in 2017 in a paper literally titled "Attention Is All You Need" — possibly the most confident paper title in ML history, and also correct. Every major language model today — GPT-4, Claude, Gemini, Phi-3 — is a Transformer.

The key mechanism is self-attention: every token in a sequence can look at every other token to understand context. The word "bank" means something different in "river bank" vs "bank account" — self-attention figures that out.

What is a Small Language Model?

Definition

A Small Language Model (SLM) is a language model under ~10 billion parameters — designed to run on consumer hardware without needing a data center, a GPU budget, or a VC-backed API bill. Same architecture as the big ones. Dramatically smaller footprint. Surprisingly capable on focused tasks.

The conventional wisdom used to be: bigger = better. More parameters, more data, more compute, better model. That was largely true — until researchers started asking a different question: what if the data was just really, really good?

Turns out a model trained on curated, high-quality text can outperform a model twice its size trained on raw internet slop. This is the entire thesis behind Phi-3, and it holds up.

When SLMs are the right call

  • Privacy is non-negotiable — You cannot paste your company's code, medical records, or legal documents into ChatGPT. Your InfoSec team will find out. SLMs keep data on-device, always.
  • Cost at scale — 10,000 code reviews a day at GPT-4 prices is a budget conversation. At Phi-3 prices, it's $0.00.
  • Offline environments — Secure facilities, air-gapped systems, planes, anywhere without internet. The model is already on your machine.
  • Focused, well-scoped tasks — Code review is narrow and well-defined. You don't need a trillion parameters to spot a nested loop. You need the right prompt and a model that knows Python.
⚠️ When SLMs will disappoint you

Complex multi-step reasoning across large documents, nuanced world knowledge, very long context tasks. If you're asking "explain the geopolitical implications of semiconductor export controls across 50 papers" — use a frontier model. Tool selection is engineering judgment. Using GPT-4 for everything is not engineering judgment, it's just laziness with a nicer price tag.

What is Phi-3 Mini?

Definition

Phi-3 Mini is a 3.8-billion parameter Small Language Model released by Microsoft Research in April 2024. It was designed from the ground up to be small enough to run on a phone, smart enough to be useful, and trained on data quality that makes larger models slightly embarrassed.

Microsoft's research team had a theory: the reason most small models are bad isn't because they're small — it's because they're trained on terrible data. Raw internet text is mostly noise. Forums, spam, SEO garbage, passive-aggressive Reddit comments. A 3B model drowning in that learns very little.

So they built synthetic "textbook quality" datasets — clean, structured, reasoning-dense content. The result: Phi-3 Mini at 3.8B parameters outperforms many 7B models on coding and reasoning benchmarks. Same idea as teaching a student with a great textbook versus a student who just scrolls Twitter for four years.

🔬 What is Quantization — and why you should care

Model weights are numbers. Normally stored as 16-bit or 32-bit floats. Quantization compresses them to 4-bit or 8-bit integers — roughly 4× smaller, with minimal quality loss on most tasks. A 3.8B FP16 model needs ~8GB RAM. The same model at INT4 needs ~2GB. Ollama handles this automatically when you pull a model. You don't do anything. It just fits on your machine. That's the magic.

What is Ollama?

Definition

Ollama is an open-source tool that lets you download and run language models locally through a single command. It handles model storage, hardware detection, quantization, and serving — and exposes a clean REST API at localhost:11434 that looks almost identical to OpenAI's API. On purpose.

Without Ollama, running Phi-3 locally requires: installing CUDA or Metal drivers, converting model weights to the right format, writing an inference server, handling memory management, and debugging segfaults at 2am. With Ollama: ollama run phi3. That's it. Done. Go home.

The important engineering insight here: Ollama runs as a local REST API server. Our Python app doesn't load the model — it makes HTTP requests to Ollama. This means the app and the model are decoupled. Swap phi3 for mistral or llama3 by changing one string. That's good abstraction.

What We're Building — and Why It's Not Trivial

We're building a local AI code reviewer that takes a deliberately broken Two Sum implementation — the kind of code that would get you a polite rejection email from any top tech company — and asks Phi-3 to tear it apart across four dimensions.

The flaw is specific: a nested loop that produces O(n²) time complexity. Correct output. Catastrophic performance. The kind of bug that passes all unit tests and then TLEs on LeetCode with n = 10,000. Phi-3 knows this. We're going to watch it explain exactly why, live, on your machine.

Step 4 — faulty_code.py

This is the defendant. Create it in the project root. We're going to write code that works perfectly, runs correctly, and would still get you rejected at a Google interview.

Pythonfaulty_code.py — in project root
# faulty_code.py
# DSA Problem: Two Sum
#
# PROBLEM: Given an array of integers and a target,
# return the indices of the two numbers that add up to target.
#
# Example: nums = [2, 7, 11, 15], target = 9 → [0, 1]
#
# This implementation is intentionally flawed.
# It produces correct output. It will also TLE on LeetCode.
# Phi-3 is going to explain exactly why.

def two_sum(nums, target):
    for i in range(len(nums)):
        for j in range(len(nums)):     # ← the problem lives here
            if i != j and nums[i] + nums[j] == target:
                return [i, j]
    return []


if __name__ == "__main__":
    nums   = [2, 7, 11, 15]
    target = 9
    result = two_sum(nums, target)
    print(f"Output: {result}")  # Prints [0, 1]. Correct. Slow. Condemned.
🎯 Explain the O(n²) problem to your viewers

The outer loop runs n times. For every single iteration, the inner loop also runs n times. That's n × n operations. For n = 100: fine. For n = 10,000: 100 million operations. For n = 100,000: 10 billion operations. LeetCode doesn't wait 10 billion operations. It gives you ~10 million before it gives you a TLE. The fix — a HashMap — does a O(1) lookup instead of a O(n) inner scan. Total complexity drops from O(n²) to O(n). Same answer, 10,000× faster on large inputs. This is why Big O exists. This is why it's asked in every Google interview.

Step 5 — src/inference.py

This is the bridge between our application and Ollama. It speaks HTTP, handles streaming, and measures performance. Create it in the src/ folder.

Pythonsrc/inference.py
import requests, json, time
from dataclasses import dataclass

@dataclass
class ReviewResult:
    content:        str
    latency_ms:     float    # time to first token
    total_time:     float    # total response time
    tokens_per_sec: float    # throughput

OLLAMA_URL = "http://localhost:11434/api/generate"
MODEL_NAME = "phi3"


def is_ollama_running() -> bool:
    try:
        return requests.get("http://localhost:11434", timeout=3).status_code == 200
    except requests.exceptions.ConnectionError:
        return False


def stream_review(prompt: str) -> ReviewResult:
    payload        = {"model": MODEL_NAME, "prompt": prompt, "stream": True}
    full_response  = ""
    first_token_at = None
    token_count    = 0
    start_time     = time.time()

    with requests.post(OLLAMA_URL, json=payload, stream=True, timeout=120) as r:
        r.raise_for_status()
        for line in r.iter_lines():
            if line:
                chunk = json.loads(line.decode("utf-8"))
                if first_token_at is None:
                    first_token_at = time.time()
                token          = chunk.get("response", "")
                full_response += token
                token_count   += 1
                print(token, end="", flush=True)   # streams to terminal
                if chunk.get("done", False):
                    break
    print()

    total = time.time() - start_time
    return ReviewResult(
        content        = full_response,
        latency_ms     = round((first_token_at - start_time) * 1000, 2) if first_token_at else 0,
        total_time     = round(total, 2),
        tokens_per_sec = round(token_count / total, 2) if total > 0 else 0
    )

Why each decision was made

DecisionWhy it matters
@dataclass return typeTyped, named return values. Not a tuple. Not a dict. An actual typed contract. This is what production Python looks like.
stream=True in requestsWe read the response line by line as it arrives — not wait for the whole thing. Ollama sends one JSON object per token. We collect them.
first_token_at timestampTime-to-first-token is a distinct metric from total time. Fast first token = responsive feel. You want both. Measure both.
is_ollama_running() checkFail fast with a clear error. Do not let the app hang for 120 seconds before telling the user "connection refused." Defensive programming.

Step 6 — src/reviewer.py

Here's where the actual intelligence lives — not in the model, but in the prompt. A well-structured prompt is the difference between "your code could be faster" and a precise, actionable engineering review that cites Big O notation and gives you working code.

Pythonsrc/reviewer.py
from inference import stream_review, ReviewResult

REVIEW_MODES = {
    "optimize": {
        "label": "⚡ Optimize",
        "instruction": (
            "You are a senior software engineer preparing a candidate for Google interviews.\n"
            "Analyze the Python code for time and space complexity.\n"
            "1. State the current Big O time complexity and explain exactly why.\n"
            "2. Explain why this causes TLE on LeetCode for large inputs.\n"
            "3. State the optimal approach and which data structure fixes it.\n"
            "4. Provide the optimized code with its new complexity stated clearly."
        )
    },
    "bug": {
        "label": "🐛 Bug Detection",
        "instruction": (
            "You are a meticulous code reviewer at a top tech company.\n"
            "Review the code for bugs and edge cases.\n"
            "1. Identify any bugs or incorrect behaviour.\n"
            "2. List edge cases that break it: empty array, single element, no solution, duplicates.\n"
            "3. Provide a corrected version that handles all of them."
        )
    },
    "security": {
        "label": "🔒 Security Scan",
        "instruction": (
            "You are a security-focused code reviewer.\n"
            "1. Check for missing input validation — type checks, null checks, bounds.\n"
            "2. Identify unsafe assumptions about the caller's input.\n"
            "3. Provide a production-hardened version."
        )
    },
    "quality": {
        "label": "✨ Code Quality",
        "instruction": (
            "You are a senior Python engineer doing a code quality review.\n"
            "1. Evaluate variable naming, clarity, and structure.\n"
            "2. Check for docstrings and type hints.\n"
            "3. Provide a clean, PEP 8 compliant version with type annotations."
        )
    }
}


def build_prompt(code: str, mode: str) -> str:
    instruction = REVIEW_MODES[mode]["instruction"]
    return f"""{instruction}

Here is the code to review:

```python
{code}
```

Provide your detailed review now:"""


def review_code(code: str, mode: str) -> ReviewResult:
    return stream_review(build_prompt(code, mode))
💡 Prompt engineering is just communication engineering

Look at the Optimize prompt: it gives Phi-3 a role ("senior engineer preparing a Google candidate"), a structured output format (4 numbered steps), and domain vocabulary (Big O, TLE, LeetCode). This isn't magic. It's the same thing you'd do when briefing a human expert — context, structure, expected output format. The model responds to this the same way a good engineer responds to a well-written spec. Garbage prompt, garbage review. Precise prompt, precise review.

📺 Video note — don't type all of app.py live

Walk through the key function below and the layout structure. The full file is already in the repo. The interesting part for your viewers isn't the Gradio boilerplate — it's the run_review() function that wires everything together and the metrics panel that shows $0.00 cost.

Python · The core functionsrc/app.py — key part
def run_review(code: str, mode: str):
    # Before touching Phi-3, confirm Ollama is alive
    if not is_ollama_running():
        return "Ollama not running. Open a terminal: ollama serve", "", "⚠️ Offline"

    # Send code to Phi-3, get back review + metrics
    result = review_code(code, mode)

    # Format what the metrics panel shows
    metrics = (
        f"Model        : phi3 (Phi-3 Mini 3.8B)\n"
        f"First token  : {result.latency_ms} ms\n"
        f"Total time   : {result.total_time} sec\n"
        f"Tokens/sec   : {result.tokens_per_sec}\n"
        f"Cloud used   : None  ✅\n"
        f"Data sent    : Nowhere  ✅\n"
        f"Cost         : $0.00  ✅"
    )
    # Three return values update three UI panels simultaneously
    return result.content, metrics, f"✅ Done in {result.total_time}s"
